# Tandem-DETR

Tandem-DETR extends D-FINE with a backbone stem feature level and bidirectional
fusion between the stem and P2 features. This release contains the M, L and XL
models for VisDrone2019-DET.

## Updates

* [2026.10.29] Release weights for Tandem-DETR-M, L, XL and StemFusion, with eval logs and TensorRT engines for T4 and A40 ([v1.0](https://github.com/KyoukoChan-SSS/Tandem-DETR/releases/tag/v1.0)).
* [2026.10.23] Release Tandem-DETR-M, L and XL for VisDrone2019-DET, with training, evaluation and ONNX export.

Dome-DETR-M keeps its window attention in FP32.
The XL engines keep 76 numerically sensitive layers in FP32.

The Tandem-DETR engines were built from ONNX graphs
exported with a rewrite that is not part of this release. Engines built from
`tools/deployment/export_onnx.py` run at about 39 / 44 / 82 ms (M / L / XL)
on T4.

## Setup

```bash
pip install -r requirements.txt
```

Tested with Python 3.11, PyTorch 2.10.0 and torchvision 0.25.0 (CUDA 12.6).

## Dataset

Extract the VisDrone2019-DET training and validation sets under
`dataset/VisDrone2019/`, naming the split directories `DET-train` and `DET-val`:

```text
dataset/VisDrone2019/
├── DET-train/
│   ├── images/
│   │   └── <image_id>.jpg
│   └── annotations/
│       └── <image_id>.txt
├── DET-val/
│   ├── images/
│   │   └── <image_id>.jpg
│   └── annotations/
│       └── <image_id>.txt
└── annotations_coco/                 # generated by the conversion command
    ├── VisDrone2019-DET_train_coco.json
    └── VisDrone2019-DET_val_coco.json
```

Each image must have a matching annotation file with the same filename stem.
Generate `annotations_coco/` and the two COCO-format JSON files from the
repository root:

```bash
python tools/dataset/visdrone2coco.py --root dataset/VisDrone2019
```

## Train

```bash
python train.py -c configs/tandem/tandem_m.yml --seed 0 --output-dir output/tandem_m
```

The HGNetv2 backbone weights are downloaded automatically for a new training run.
Add `-r output/tandem_m/last.pth` to resume. Configs for M, L and XL are
`configs/tandem/tandem_{m,l,x}.yml`; Slurm wrappers are in `scripts/`.

## Evaluate

```bash
python train.py -c configs/tandem/tandem_m.yml --test-only \
    -r output/tandem_m/best_stg2.pth
```

Evaluation and export use the checkpoint produced by training above. Resume,
evaluation and export restore the backbone from that checkpoint.

## Inference and ONNX

```bash
pip install -r tools/deployment/requirements.txt opencv-python-headless
python tools/inference/torch_inf.py -c configs/tandem/tandem_m.yml \
    -r output/tandem_m/best_stg2.pth -i image.jpg
python tools/deployment/export_onnx.py -c configs/tandem/tandem_m.yml \
    -r output/tandem_m/best_stg2.pth -o output/tandem_m/model.onnx --verify
python tools/inference/onnx_inf.py --onnx output/tandem_m/model.onnx --input image.jpg
```

Export uses the configuration's input size (800x800) and batch 1 by default.
Add `--dynamic-batch` to export a variable batch dimension; with `--verify`,
batches 1 and 2 are compared against PyTorch. Spatial dimensions remain fixed.
Inputs are RGB float32 in [0, 1], resized directly without padding, and int64
`orig_target_sizes` in (width, height) order. Outputs are `labels`, `boxes`
(xyxy in original-image pixels) and `scores`. Simplification is optional:
install `onnxsim` and add `--simplify`.

```bash
python tools/benchmark/get_info.py -c configs/tandem/tandem_m.yml
python tools/export_weights.py output/tandem_m/best_stg2.pth output/tandem_m/weights.pth
```

TensorRT, OpenVINO and C++ examples are inherited from upstream and are not
part of the validated Tandem-DETR inference path.
